# 뉴스 브리핑 데스크톱 앱 — 설계서

> 상태: 설계 단계 (v0.1, 구현 착수 전)
> 이 문서는 확정된 결정과 미결 사항을 함께 기록한다. 구현은 이 문서 승인 후 마일스톤 순서대로 진행한다.

---

## 1. 목표

매일 아침, 사용자가 등록한 관심 주제에 대한 뉴스와 논문을 자동으로 수집해 **중요도 순 10개**를 보여주는 개인용 데스크톱 앱. 모든 외부 서비스는 사용자가 자기 API 키를 직접 등록해 사용한다(서버 없음, 전액 사용자 소유).

### 핵심 사용자 시나리오

1. 아침에 PC를 켠다 → 앱이 백그라운드에서 조사한 뒤 OS 알림을 보낸다. 알림을 클릭하면 오늘의 브리핑 10개가 제목 리스트로 뜬다.
2. 제목을 훑다가 관심 가는 항목에서 **[원본 가기]** → 기본 브라우저로 원문 열림.
3. **[요약정리]** → 앱 안에서 LLM이 정리한 요약을 본다.
4. **[더보기]** → 11위 이하 기사 목록을 10개씩 추가로 본다.
5. 남겨두고 싶은 기사에서 **[노션 저장]** → 사용자의 노션 DB에 아카이빙.

## 2. 확정된 결정 사항

| 항목 | 결정 | 비고 |
|---|---|---|
| 플랫폼 | Windows + macOS | Electron 기반 크로스플랫폼 |
| 자동 실행 | 8시 이후 PC 켜지면 **1회 강제 실행**, 이후는 사용자가 앱을 열 때만 | 하루 1회 자동 조사 |
| 창 닫기 | **닫으면 앱 종료** (트레이에 숨지 않음) | 아침 실행은 로그인 항목 등록이 보장 (§5) |
| 콘텐츠 수집 | 뉴스 API + 논문 API + LLM API **이원화** | 무료 소스 우선 |
| 요금제 정책 | **무료 기준**, 유료 제공사는 UI에 명확히 표시 | 배지 + 설정 화면 안내 |
| 주제 설정 | 자유 키워드 + 미리 정의된 카테고리 **병행** | |
| 노션 아카이빙 | 기사별 **[노션 저장] 버튼 클릭 시** 개별 저장 | 자동 일괄 저장 안 함 |
| 노션 노출 | **연결을 마친 사용자에게만** 관련 UI 표시 | 미연결 시 버튼 자체가 없음 (§9.0) |
| 로컬 저장 | **DB 사용 안 함**, JSON 파일만 | 일반 사용자 설치 부담 제거 (§3) |
| 본 기사 | **이미 본 기사는 다시 올리지 않음** (기본 30일 기억) | 창을 열어 실제로 표시된 것만 "봤다"로 기록 (§6.1) |
| API 사용량 | **기본 설정 하루 10회 미만** 목표 | 호출 상한·후보 축소·사용량 표시 (§7.3) |
| API 키 저장 | **OS 자격증명 저장소 암호화** (Electron `safeStorage`) | Windows DPAPI / macOS Keychain |
| LLM 지원 | **여러 제공사 선택 지원** (Upstage Solar 포함) | 순서대로 폴백 |
| 로컬 LLM | **설치된 로컬 모델(Qwen 등) 우선 사용** | 키 불필요·비용 0·호출 제한 없음 (§7.4) |
| 업그레이드 | **GitHub Releases + electron-updater** | 자동 다운로드/설치 |
| 아침 알림 | **OS 알림만** 띄우고, 클릭하면 창이 열림 | 작업 방해 최소화 |
| 뉴스/논문 범위 | **최초 실행 온보딩에서 사용자가 설정**, 그 값이 기본값 | §8.1 |
| 코드 서명 | **하지 않음** | 첫 설치 시 OS 경고 수동 통과, 안내 문서 제공 |
| 기록 보관 | **당일치만 유지** | 장기 보관은 노션 아카이빙이 담당 |

## 3. 기술 스택

| 레이어 | 선택 | 이유 |
|---|---|---|
| 앱 셸 | Electron | Windows/macOS 동시 지원, 트레이 상주, 자동 업데이트 생태계 |
| UI | React + TypeScript + Vite | 리스트/패널 중심 UI에 적합, 빠른 개발 |
| 메인 프로세스 | Node.js (TypeScript) | 네트워크 호출·스케줄러·키 저장 담당 |
| 로컬 저장 | **JSON 파일** (DB 없음) | 아래 참고 |
| 설정 저장 | 자체 JSON 저장소 (`node:fs`) | 비밀이 아닌 설정(주제, 순서, 실행 시각). §10의 원자적 교체·손상 복구를 직접 구현하므로 별도 라이브러리를 쓰지 않는다 |
| 비밀 저장 | `safeStorage` + 암호문 파일 | API 키는 평문으로 디스크에 두지 않음 |
| 패키징 | `electron-builder` | NSIS(Win) / DMG(Mac), 코드 서명 없음 |
| 업데이트 | `electron-updater` | GitHub Releases를 피드로 사용 |

> **네이티브 모듈 없음 원칙**: 일반 사용자용 앱이므로 데이터베이스(SQLite 등)를 쓰지 않는다. SQLite는 플랫폼별 네이티브 빌드가 필요해 설치·업데이트·배포가 복잡해지는데, 이 앱이 다루는 데이터는 **당일치 기사 수십 건**뿐이라 JSON 파일로 충분하다. 모든 의존성은 순수 JavaScript만 사용한다. 결과적으로 사용자는 별도 런타임·빌드 도구 설치 없이 설치 파일 하나로 끝난다.

> **보안 원칙**: 렌더러는 `nodeIntegration: false`, `contextIsolation: true`. 모든 외부 호출과 키 접근은 메인 프로세스에서만 수행하고, 렌더러에는 preload의 제한된 IPC 채널만 노출한다. **API 키는 절대 렌더러로 전달하지 않는다**(설정 화면에는 마스킹된 표시값과 검증 결과만 보냄).

## 5. 자동 실행 로직 (기능 2)

사용자 결정: **"8시 이후 컴퓨터 켜지면 강제 실행 1번, 나머지는 사용자가 직접 앱을 열 때만."**

앱은 OS 로그인 항목으로 등록되어 부팅 때 백그라운드에서 시작한다. **다음 아침 실행을 보장하는 것은 트레이 상주가 아니라 이 로그인 항목 등록이다.** 그래서 사용자가 앱을 완전히 종료해 두어도 다음 날 아침은 정상 동작한다.

```
앱 시작(부팅·수동 실행) 또는 절전 복귀
        │
        ├─ 오늘(local) 이미 조사함?  ── 예 ──▶ 아무것도 안 함.
        │                                     (사용자가 열면 캐시 표시 + 수동 새로고침 버튼)
        └─ 아니오
              │
              ├─ 현재 시각 ≥ 08:00 ──▶ 즉시 1회 수집 실행 → OS 알림 발송 → lastAutoRunDate = 오늘
              │
              └─ 08:00 이전 ──▶ 오늘 08:00에 1회 실행되도록 타이머 예약
```

- 절전/최대절전 복귀는 `powerMonitor`의 `resume` 이벤트로 재평가한다(타이머만으로는 절전 중 시각 경과를 놓칠 수 있음).
- `lastAutoRunDate`는 로컬 날짜 기준. 자정을 넘겨 켜면 다음 날 브리핑이 새로 생성된다.
- 자동 실행 시각(기본 08:00)과 OS 시작 시 자동 실행 여부는 설정에서 변경 가능.

### 창을 닫으면 종료된다

사용자 결정: **창의 닫기(X)를 누르면 앱이 완전히 종료된다.** 트레이에 숨지 않는다.

이렇게 해도 다음 아침 조사는 문제가 없다. 위 판단은 **앱이 시작될 때마다** 수행되고, 앱은 로그인 항목으로 등록되어 부팅 때 다시 시작되기 때문이다.

빈틈은 하나뿐이다 — **08:00 이전에 PC를 켜고 8시가 되기 전에 앱을 종료한 경우**(그리고 PC를 며칠째 켜둔 채 앱만 꺼둔 경우). 예약해 둔 타이머가 앱과 함께 사라진다. 이 빈틈은 위 흐름도의 **따라잡기 실행**이 메운다. 사용자가 앱을 여는 순간 "8시 이후인데 오늘 아직 조사 안 함"에 해당하므로 그 자리에서 바로 조사한다. 알림은 놓쳐도 내용은 놓치지 않는다.

트레이 아이콘은 **앱이 실행 중인 동안에만** 존재한다. 부팅 후 창 없이 8시를 기다리는 동안 앱이 살아 있다는 것을 알리고, 브리핑 열기·종료 메뉴를 제공하는 역할이다.

> PC를 항상 켜두고 앱도 계속 띄워 두는 사용자를 위해 "창을 닫아도 백그라운드 유지"를 설정 옵션으로 둘 수 있다. **기본값은 off**(닫으면 종료)이며, 실제로 필요하다는 요청이 있을 때 추가한다.

### 알림 동작

자동 조사가 끝나면 **창을 강제로 띄우지 않고 OS 알림만** 보낸다.

- 알림 문구: `오늘의 브리핑 10건이 준비됐습니다 — {1위 기사 제목}`
- 알림을 클릭하면 브리핑 창이 열린다. 무시하면 트레이 아이콘에 미확인 배지만 남는다(앱이 실행 중인 동안).
- 수집이 전부 실패하면 실패 사유를 담은 알림을 보낸다(조용히 실패하지 않는다).

## 6. 콘텐츠 파이프라인

```
1. 쿼리 생성     사용자 키워드 + 선택 카테고리 → 소스별 검색어로 변환
2. 수집          뉴스 소스 + 논문 소스 병렬 호출 (각 카테고리 내에서는 순서 기반 폴백)
3. 정규화        서로 다른 응답을 공통 Article 형태로 변환
4. 중복 제거     URL 정규화 + 제목 유사도(정규화 후 토큰 자카드 ≥ 0.8) 기준 병합
5. 사전 필터     최근 N시간 이내(뉴스 기본 48h) / 논문 기본 14일 이내로 축소, 최대 60건
6. 본 기사 제외  seen-index.json과 대조해 이미 본 기사를 걸러냄  ← §6.1
7. 후보 축소     규칙 점수 상위 25건만 LLM으로 보냄 (나머지는 규칙 점수만 사용)
8. 중요도 스코어링  LLM 배치 평가 1회 + 규칙 기반 가중치
9. 저장          briefing.json 하나로 통째로 저장 (임시 파일 쓰고 rename)
10. 표시         상위 10개 제목만 노출, [더보기]로 10개씩 추가
```

> 6단계를 LLM 호출(8단계) **앞에** 두는 것이 중요하다. 이미 본 기사를 먼저 걸러내면 평가할 후보가 줄어 토큰도 함께 절약된다.

### 6.1 이미 본 기사 제외

같은 기사가 다음 날 또 올라오는 것을 막는다.

**무엇을 "봤다"고 볼 것인가** — 알림만 뜨고 창을 열지 않은 날의 기사는 본 것이 아니다. 다음 두 경우에만 본 것으로 기록한다.

1. 브리핑 창을 열어 **화면에 제목이 실제로 표시된** 기사 ([더보기]로 펼친 항목 포함)
2. [원본 가기] · [요약정리] · [노션 저장]을 누른 기사

기록은 `seen-index.json`에 URL 해시, 제목 유사도 비교용 정규화 토큰, 본 시각만 남긴다(본문·요약은 저장하지 않음).

**거르는 방식**

| 상황 | 처리 |
|---|---|
| URL이 같음 | 완전 제외. 목록에 올리지 않음 |
| URL은 다르지만 제목 유사도 ≥ 0.8 (같은 사건의 다른 매체 기사, 재탕 기사) | 기본 제외 |
| 유사하지만 새로운 내용이 붙은 후속 기사 | 제목 유사도만으로는 구분이 어렵다. 설정의 **"후속 기사도 보기"**(기본 off)를 켜면 제외하지 않고 `후속` 배지를 달아 보여준다 |

**안전장치** — 걸러낸 탓에 볼 게 없어지면 곤란하므로:

- 제외 후 남은 기사가 **3건 미만이면 제외를 풀고** 전부 보여준다. "새 기사가 적어 이전에 본 기사도 포함했습니다"라고 알린다.
- [더보기] 영역 아래에 **[이미 본 기사 포함해서 보기]** 토글을 둔다. 끄고 켜는 것만으로 즉시 다시 볼 수 있다(재수집 없음).
- 논문은 뉴스와 달리 며칠에 걸쳐 다시 눈에 띄는 편이 나을 수 있으므로, 제외 대상에서 논문을 뺄지 설정에서 고를 수 있게 한다(기본: 논문도 제외).

**보관 기간** — 기본 30일. 그보다 오래된 기록은 지운다. 기사 60건 × 30일 ≈ 1,800개 해시로 파일은 100KB 안팎이다. 설정에서 7·30·90일 중 고를 수 있고, [기록 비우기]로 전부 지울 수 있다.

### 6.2 중요도 스코어링

LLM 한 번의 호출에 후보 기사의 (제목 + 출처 + 짧은 스니펫 + 발행시각) 목록을 넘겨 각 항목에 **0~100 점과 한 줄 사유**를 받는다. 최종 점수는 가중 합산:

```
final = 0.60 × llmScore          (LLM이 판단한 주제 관련성·영향력·신규성)
      + 0.25 × keywordMatch      (사용자 키워드 직접 일치 정도)
      + 0.15 × recency           (발행 시각 기반 시간 감쇠)
```

- LLM 키가 하나도 없거나 전부 실패하면 `keywordMatch + recency`만으로 정렬하고, UI에 "LLM 미적용 — 단순 정렬" 배너를 띄운다. 앱이 죽지 않고 동작하는 것이 원칙.
- 가중치는 상수로 시작하되 설정 노출은 추후 검토.

### 6.3 요약 생성 (기능 3)

- 기본값: **지연 생성**. [요약정리]를 처음 누른 시점에 LLM 호출 → 결과를 `briefing.json`에 캐시하고 이후에는 재호출하지 않는다. (무료 티어 사용량 절약 목적)
- 설정 옵션: "아침에 상위 10개 요약 미리 생성" — **기본 off**. 켜면 하루 LLM 호출이 10회 늘어난다는 점을 설정 화면에 명시한다. 단 **로컬 모델이 1순위면 비용이 0이므로 켜기를 권한다**(§7.4).
- 요약 형식: 한 줄 핵심 + 불릿 3~5개 + 키워드 태그. 언어는 한국어 고정(설정으로 변경 가능하게 둠).
- 원문 본문 확보 방법: 1차로 API가 주는 description/abstract 사용, 부족하면 원문 URL을 가져와 본문 추출(`@mozilla/readability`). 추출 실패 시 확보된 스니펫만으로 요약하고 UI에 "요약 근거 제한적" 표시.

### 7.2 폴백 체인 (기능 5)

- 키는 카테고리별로 **여러 개 저장 가능**하고, 사용자가 **순서를 지정**한다(▲▼ 버튼. 드래그는 필요해지면 추가).
- 호출 시 순서대로 시도하며, 다음 경우에 다음 항목으로 넘어간다: 인증 실패(401/403), 한도 초과(429), 서버 오류(5xx), 타임아웃(기본 15초), 응답 파싱 실패.
- 잘못된 요청(400) 같은 사용자 설정 문제는 폴백하지 않고 오류를 그대로 보여준다(조용히 넘어가면 원인 파악이 어려움).
- 각 항목의 마지막 성공/실패 시각과 사유를 저장해 설정 화면에 상태 배지로 표시한다.
- 설정 화면에 항목별 **[연결 테스트]** 버튼 제공 — 최소 비용 호출로 키 유효성 검증.

### 7.3 API 호출 최소화 전략

무료 한도 안에서 쓰는 것이 목표다. **기본 설정으로 하루 총 10회 미만**을 목표치로 잡는다.

#### 수집 단계 — 호출 횟수를 곱셈이 아니라 덧셈으로

가장 큰 위험은 `키워드 수 × 소스 수`만큼 호출이 늘어나는 것이다.

1. **키워드 묶어서 호출**: 소스가 OR 문법을 지원하면 여러 키워드를 한 번에 묶어 1회로 처리한다. 지원하지 않는 소스(네이버 등)는 키워드마다 호출이 필요하므로, 아래 상한이 적용된다.
2. **카테고리당 1개 소스만 사용**: 폴백 체인은 순차 실행이라 첫 번째 소스가 성공하면 나머지는 호출하지 않는다. "여러 소스 결과 합치기"는 옵션으로 두되 **기본 off**.
3. **호출 상한**: 1회 수집당 소스별 최대 호출 수(기본 5회)와 전체 상한(기본 12회)을 둔다. 초과하면 중단하고 "키워드가 많아 일부만 조회했습니다"라고 알린다.
4. **페이지네이션 금지**: 각 호출은 1페이지만 요청한다(최대 건수로).
5. **조건부 요청**: RSS 등 HTTP 소스는 `ETag` / `Last-Modified`를 저장했다가 재요청 시 보내고, 304면 본문을 받지 않는다.
6. **한도 초과 기억**: 429를 받은 소스는 당일 재시도하지 않고 바로 다음 소스로 넘어간다(무의미한 호출 반복 방지).
7. **수동 새로고침 쿨다운**: 기본 10분. 연타로 한도를 태우는 것을 막는다.

#### LLM 단계 — 호출 1회, 토큰 최소

1. **스코어링은 배치 1회**: 기사당 호출은 금지. 후보 전체를 한 번의 호출로 평가한다.
2. **LLM에 넣기 전 규칙으로 선별**: 수집된 60건을 키워드 일치·최신성·소스 기준으로 **25건까지 줄여서** LLM에 보낸다. 나머지는 LLM 없이 규칙 점수만으로 [더보기] 뒤쪽에 배치한다.
3. **입력 압축**: 제목 + 출처 + 발행시각 + 스니펫 200자로 자른다. 본문은 넣지 않는다.
4. **출력 압축**: `[{i, s, r}]` 형태(색인·점수·사유)로 받고 사유는 40자 이내로 제한한다.
5. **모델 분리**: 스코어링은 저가·고속 모델, 요약은 품질 모델을 쓰도록 설정을 나눈다. 기본값은 둘 다 저가 모델.
6. **요약은 지연 생성 + 캐시**: 사용자가 [요약정리]를 누른 것만 1회 생성하고 재호출하지 않는다. "아침에 미리 요약" 옵션은 **기본 off**(켜면 하루 10회가 추가된다고 화면에 명시).
7. **요약 입력 제한**: 원문 본문 추출 시 앞부분 6,000자까지만 사용한다.
8. **일일 상한**: LLM 호출 하루 최대 횟수(기본 20회)를 두고, 도달하면 중단하고 알린다.

#### 사용량 가시화

설정 화면에 오늘의 호출 횟수를 제공사별로 보여준다(`수집 3회 / 스코어링 1회 / 요약 2회`). 사용자가 한도를 체감할 수 있어야 스스로 조절할 수 있다. 카운터는 매일 0시에 초기화한다.

> 기본 설정 기준 하루 예상 호출: 수집 2~4회 + 스코어링 1회 + 요약 2~3회 = **5~8회**.

> **로컬 LLM은 예외다.** 위 LLM 절감 규칙은 무료 한도를 아끼기 위한 것이므로, 사용자 PC에서 도는 모델에는 적용하지 않는다(§7.4). 로컬 모델이 1순위면 LLM 호출은 사실상 무제한이고 수집 호출만 관리 대상으로 남는다.

### 7.4 로컬 LLM 지원 (Qwen 등)

사용자 PC에 Qwen 같은 모델이 이미 설치돼 있다면 그것을 우선 사용한다. **비용 0, 호출 제한 없음, 기사 내용이 외부로 나가지 않음** — 이 앱의 제약(무료 기준, 호출 최소화)과 정확히 맞아떨어진다.

#### 어댑터 하나로 커버한다

로컬 실행기들은 대부분 **OpenAI 호환 API**를 제공하므로 별도 구현이 필요 없다. 사용자는 주소와 모델 이름만 지정한다.

| 실행기 | 기본 주소 | 비고 |
|---|---|---|
| Ollama | `http://localhost:11434/v1` | 백그라운드 서비스로 상주해 아침 자동 실행에 가장 적합 |
| LM Studio | `http://localhost:1234/v1` | 사용자가 서버를 켜 둬야 함 |
| llama.cpp server | `http://localhost:8080/v1` | |
| vLLM | `http://localhost:8000/v1` | |

같은 어댑터로 Qwen 클라우드(DashScope)의 OpenAI 호환 엔드포인트도 처리할 수 있다. 주소와 키만 달라진다.

#### 자동 감지

설정·온보딩 화면의 **[내 컴퓨터에서 모델 찾기]** 버튼을 누르면 위 주소들에 `/v1/models`(Ollama는 `/api/tags`도)를 질의해 **설치된 모델 목록을 보여주고 고르게 한다.** 사용자가 주소나 모델 이름을 외울 필요가 없다. 로컬 호출이라 실패해도 비용이 들지 않으므로 온보딩에서 한 번 자동으로 시도해 본다.

#### 로컬이라서 달라지는 것

- **호출 제한 해제**: §7.3의 상한은 무료 한도를 아끼기 위한 것이므로 로컬 모델에는 적용하지 않는다. 로컬이 1순위면 "아침에 요약 미리 생성"을 켜도 비용이 0이라 **켜기를 권한다**(설정 화면에서 안내).
- **배치 쪼개기**: 로컬 모델은 컨텍스트 길이가 짧은 경우가 많다. 클라우드는 25건을 1회로 보내지만, 로컬은 호출 수 제한이 없으므로 **작게 나눠 여러 번 호출**한다(기본 8건씩). 제공사별로 배치 크기를 설정에 둔다.
- **느린 응답 허용**: CPU만으로 돌리면 스코어링에 수 분이 걸릴 수 있다. 아침 조사는 백그라운드에서 돌고 끝나면 알림으로 알리는 구조라 사용자가 기다리지 않는다. 타임아웃은 로컬 제공사에 한해 길게(기본 5분) 잡는다.

#### 주의점

- **작은 모델은 JSON 형식을 어길 수 있다.** 스코어링 응답 파싱에 실패하면 1회 재시도하고, 그래도 실패하면 폴백 체인의 다음 제공사로 넘어간다. 형식을 지키지 못하는 모델이면 설정 화면의 [연결 테스트]에서 미리 걸러 알려준다.
- **요약 품질은 모델 크기에 좌우된다.** 특히 한국어 요약은 작은 모델에서 떨어질 수 있으므로, 사용자가 직접 비교해 보고 순서를 정할 수 있게 한다(이미 폴백 순서를 사용자가 정하는 구조라 추가 설계가 필요 없다).
- **아침에 서버가 꺼져 있을 수 있다.** 로컬을 1순위, 무료 클라우드를 2순위로 두면 연결 실패 시 자동으로 넘어간다. 이때 "로컬 모델에 연결하지 못해 클라우드로 처리했습니다"를 화면에 표시한다.

### 7.5 키 저장

- 저장: 키 문자열을 `safeStorage.encryptString()`으로 암호화해 `userData/credentials.enc`에 보관. 메타데이터(제공사, 라벨, 순서, 활성 여부)는 평문 JSON에 두되 **키 본문은 포함하지 않는다**.
- 조회: 메인 프로세스에서만 복호화. 렌더러에는 `sk-...abcd` 형태의 마스킹 값만 전달.
- `safeStorage.isEncryptionAvailable()`가 false인 환경(일부 Linux 등)에서는 저장을 거부하고 사유를 안내한다.
- 로그·오류 메시지에 키가 찍히지 않도록 마스킹 필터를 공통 적용한다.

## 8. 화면 설계

### 8.1 온보딩 마법사 (최초 실행 시 1회)

설치 후 처음 앱을 열면 4단계 마법사가 뜬다. 여기서 정한 값이 **앱의 기본 설정**이 되고, 이후 설정 화면에서 언제든 바꿀 수 있다.

| 단계 | 내용 |
|---|---|
| 1. 관심 주제 | 키워드 입력 + 카테고리 선택 (최소 1개 필요) |
| 2. 수집 범위 | **뉴스 포함 / 논문 포함** 선택 (둘 다, 뉴스만, 논문만), 각각의 기간·건수 기본값 |
| 3. API 키 | 먼저 **내 컴퓨터의 로컬 모델을 자동으로 찾아** 발견되면 1순위로 제안한다(§7.4). 그다음 제공사별 키 입력 — 무료/부분무료/유료 배지와 발급 페이지 링크 제공. **전부 건너뛰어도 완료 가능** (키 불필요 소스로 동작) |
| 4. 노션 연결 | 노션 준비 절차를 단계별로 안내 (§9.1). **건너뛰기 가능** — 건너뛰면 앱에서 노션 기능이 아예 보이지 않는다 |

- 각 단계에 "왜 필요한지" 한 줄 설명을 붙인다. 특히 LLM 키가 없으면 요약·중요도 판단이 비활성화된다는 점을 3단계에서 명시.
- 마법사 완료 시 `onboardingCompleted = true` 기록. 이후에는 뜨지 않는다.
- 마법사에서 즉시 첫 브리핑을 한 번 실행해 결과를 보여준다(설정이 제대로 됐는지 확인 목적).

```
├───────────────────────────────────────────────────────────┤
│                      [ 더보기 ]                            │
└───────────────────────────────────────────────────────────┘
```

- 처음에는 **제목 중심 10개**. 본문·요약은 접힌 상태.
- [더보기] 클릭 시 11~20위를 추가로 붙인다(최대 수집분까지).
- 뉴스/논문 구분 배지, 중요도 점수, 출처, 상대 시각 표시.
- LLM 미적용·일부 소스 실패 시 상단에 상태 배너.
- **[노션] 버튼은 노션 연결을 마친 사용자에게만 보인다.** 연결 전에는 버튼 자리 자체가 없어 화면이 단순해진다(회색 비활성 버튼도 두지 않는다). 설정에서 연결하면 즉시 나타난다.

### 8.3 요약 패널

- 우측에서 슬라이드되는 패널. 한 줄 핵심 → 불릿 요약 → 키워드 → [원본 가기] / [노션 저장](연결된 경우에만).
- 생성 중에는 스켈레톤 + 사용 중인 LLM 제공사 표시. 실패 시 재시도 버튼과 폴백된 제공사 안내.

### 8.4 설정

- **주제**: 키워드 입력(칩 형태 추가/삭제) + 카테고리 체크박스(IT/과학, 경제, 의학·바이오, 정책, 산업 등).
- **API 키**: 카테고리별 목록. 각 행에 제공사명, 라벨, 마스킹 키, 요금제 배지(무료/부분무료/유료), 상태(성공·실패·미검증), [테스트] [삭제], 드래그 핸들로 순서 변경.
- **실행**: 자동 실행 시각(기본 08:00), OS 시작 시 자동 실행 on/off, 알림 표시 on/off.
- **수집 범위**: 뉴스 포함 / 논문 포함 여부(온보딩에서 정한 값이 초기값), 뉴스 최근 N시간, 논문 최근 N일, 소스별 최대 건수.
- **본 기사 처리**: 기억 기간(7/30/90일), 후속 기사도 보기 on/off, 논문도 제외할지 on/off, [기록 비우기].
- **사용량**: 오늘의 제공사별 호출 횟수, 일일 상한 설정, 아침에 요약 미리 생성 on/off(켜면 호출이 늘어난다는 안내 포함).
- **노션(선택)**: 연결 상태 표시, [노션 연결하기] / [연결 다시 하기](온보딩 4단계와 같은 안내), 대상 DB 확인, [연결 해제]. 연결 해제 시 브리핑 화면의 노션 버튼도 함께 사라진다.

### 8.5 업그레이드 (기능 6)

- 현재 버전 / 최신 버전 / 릴리즈 노트 표시.
- [업데이트 확인] → [다운로드] → [설치 후 재시작]. `electron-updater`가 GitHub Releases의 `latest.yml` / `latest-mac.yml`을 피드로 사용.
- 자동 확인 주기: 앱 시작 시 1회 + 24시간마다. 다운로드는 **사용자 확인 후** 진행(조용한 자동 설치는 하지 않음).
- **코드 서명은 하지 않는다**(결정 완료). 따라서 첫 설치 시 macOS는 Gatekeeper 경고, Windows는 SmartScreen 경고가 뜬다. 사용자가 수동으로 통과하는 방법을 README와 릴리즈 노트에 안내한다. 업데이트 설치 시에도 같은 경고가 날 수 있음을 업그레이드 화면에 명시한다.

## 9. 노션 아카이빙 (기능 7)

### 9.0 노출 조건

노션은 **연결을 마친 사용자에게만 보이는 선택 기능**이다. 앱은 노션 연결 상태를 세 가지로 관리한다.

| 상태 | 조건 | UI |
|---|---|---|
| `unconfigured` | 토큰 없음 또는 대상 DB 미선택 | 브리핑·요약 패널에서 노션 관련 요소를 **렌더링하지 않음**. 설정 화면의 "노션 연결(선택)" 항목만 존재 |
| `connected` | 토큰 유효 + 대상 DB 접근 확인됨 | [노션 저장] 버튼 노출, 저장된 기사에는 체크 표시 |
| `needs_reconnect` | 저장 시도 중 401/403/404 발생 (토큰 폐기, 권한 회수, DB 삭제 등) | 버튼은 유지하되 클릭 시 "노션 연결이 끊어졌습니다" 안내 + 설정으로 이동 |

- 상태 판정은 메인 프로세스가 하고, 렌더러에는 `notionStatus`만 내려보낸다(토큰은 전달하지 않음).
- 노션을 쓰지 않는 사용자는 이 기능의 존재를 신경 쓸 필요가 없다는 것이 원칙.

### 9.1 노션 연결 준비 안내

**설치 파일(인스톨러)에는 자세한 안내를 넣지 않는다.** Windows NSIS는 텍스트 페이지 한두 장이 한계고 macOS DMG는 드래그 앤 드롭 화면뿐이라, 그림·링크·검증이 필요한 노션 설정을 설치 마법사에서 제대로 안내할 수 없다. 대신 **앱 안의 온보딩 4단계**에서 안내한다. 앱 안에서 하면 버튼으로 노션 페이지를 열어 주고, 붙여넣은 값을 즉시 검증하고, 막힌 단계를 짚어 줄 수 있다.

설치 마법사는 마지막 화면에 "설치 완료 — 앱을 실행하면 초기 설정을 안내합니다" 한 줄과 실행 체크박스만 둔다.

온보딩 4단계 화면 (각 단계에 그림 + [열기] 버튼 + 확인 표시):

| 단계 | 사용자 행동 | 앱이 돕는 것 |
|---|---|---|
| 1 | 노션 통합(Integration) 만들기 | [노션 통합 페이지 열기] 버튼으로 브라우저를 띄움 |
| 2 | 발급된 시크릿 토큰 복사 → 앱에 붙여넣기 | 붙여넣는 즉시 형식 검사 + [연결 테스트]로 유효성 확인 |
| 3 | **아카이브를 둘 노션 페이지에 통합 연결 권한 주기** | 가장 많이 막히는 단계. 그림으로 안내하고, 다음 단계에서 실제로 확인해 줌 |
| 4 | 대상 페이지 선택 | 앱이 접근 가능한 페이지 목록을 불러와 보여줌. 목록이 비어 있으면 "3단계의 권한 부여가 안 된 것 같습니다"라고 원인을 짚어 줌 |
| 5 | 완료 | 앱이 필요한 속성을 갖춘 데이터베이스를 자동 생성하고, 테스트 페이지 1건을 저장해 본 뒤 지운다 |

- 같은 안내를 설정 화면의 [노션 연결 다시 하기]에서도 동일하게 볼 수 있다.
- 노션의 메뉴 이름은 노션 업데이트에 따라 달라질 수 있으므로, 화면 문구는 짧게 유지하고 상세 가이드 문서 링크를 함께 둔다.

### 9.2 저장 동작

앱이 만든(또는 사용자가 고른 기존) 노션 데이터베이스에 페이지를 생성한다. 필요한 속성:

| 노션 속성 | 타입 | 내용 |
|---|---|---|
| Title | title | 기사 제목 |
| URL | url | 원문 링크 |
| Source | rich_text | 출처 |
| Type | select | 뉴스 / 논문 |
| Published | date | 발행일 |
| Score | number | 중요도 점수 |
| Topics | multi_select | 매칭된 사용자 키워드 |
| ArchivedAt | date | 저장 시각 |

- 페이지 본문에는 요약(있으면)과 원문 링크를 넣는다. 요약이 아직 없으면 저장 시점에 생성할지 물어본다.
- 같은 URL이 이미 저장돼 있으면(`archive-index.json` 조회) 중복 생성 대신 기존 페이지 링크를 보여준다.
- 저장 성공 시 리스트 행에 체크 표시가 남는다(`archive-index.json`에 URL 해시·페이지 ID 기록).
- 사용자가 고른 기존 DB에 속성이 없으면 앱이 추가를 제안한다. 거절하면 있는 속성만 채우고 나머지는 본문에 적는다.

## 10. 데이터 모델 (초안)

```ts
type Article = {
  id: string;              // url 정규화 해시
  runId: string;
  type: 'news' | 'paper';
  title: string;
  url: string;
  source: string;          // 매체명 또는 저널/arXiv 카테고리
  authors?: string[];
  publishedAt?: string;    // ISO8601
  snippet?: string;        // API 제공 description/abstract
  llmScore?: number;       // 0~100
  scoreReason?: string;
  finalScore: number;
  matchedKeywords: string[];
  summary?: string;        // 생성 후 캐시
  summaryProvider?: string;
  archivedAt?: string;
  notionPageId?: string;
  fetchedAt: string;
  providerKey: string;     // 어느 소스에서 왔는지
};

type ArchiveRecord = {  // 기사 삭제 후에도 남는 경량 기록 (중복 저장 방지용)
  urlHash: string;
  notionPageId: string;
  archivedAt: string;
};

type SeenRecord = {     // 이미 본 기사 (기본 30일 보관)
  urlHash: string;
  titleTokens: string[];  // 제목 유사도 비교용 정규화 토큰
  type: 'news' | 'paper';
  seenAt: string;
};

type Run = {
  id: string;
  startedAt: string;
  finishedAt?: string;
  trigger: 'auto' | 'manual';
  topics: string[];
  categories: string[];
  providerResults: { providerKey: string; ok: boolean; count: number; error?: string }[];
  llmProvider?: string;
};

type CredentialMeta = {
  id: string;
  category: 'news' | 'paper' | 'llm' | 'notion';
  providerKey: string;     // 'naver' | 'gemini' | 'upstage' ...
  label: string;           // 사용자가 붙인 이름
  order: number;           // 폴백 순서
  enabled: boolean;
  pricing: 'free' | 'freemium' | 'paid';
  lastCheckedAt?: string;
  lastStatus?: 'ok' | 'auth_error' | 'rate_limited' | 'server_error' | 'unknown';
};
```

### 저장 파일 (DB 없음)

모든 데이터는 `app.getPath('userData')` 아래 JSON 파일 몇 개로 관리한다.

| 파일 | 내용 | 크기 |
|---|---|---|
| `briefing.json` | 오늘의 `Run` 1건 + `Article` 배열(최대 60건, 요약 캐시 포함) | 수백 KB 이하 |
| `settings.json` | 주제, 카테고리, 수집 범위, 실행 시각, 제공사 순서·메타데이터, 온보딩 완료 여부 | 수 KB |
| `archive-index.json` | `ArchiveRecord` 배열 (노션 저장 기록) | 수십 KB |
| `seen-index.json` | 이미 본 기사의 URL 해시 + 제목 토큰 + 본 시각 (기본 30일) | 100KB 안팎 |
| `usage.json` | 오늘의 제공사별 호출 횟수 (0시 초기화) | 1KB 미만 |
| `credentials.enc` | `safeStorage`로 암호화된 API 키 묶음 | 수 KB |

- **원자적 저장**: 항상 `파일명.tmp`에 쓰고 `fs.rename()`으로 교체한다. 저장 중 앱이 종료돼도 기존 파일이 깨지지 않는다.
- **손상 복구**: 읽을 때 JSON 파싱에 실패하면 해당 파일을 `.corrupt`로 옮기고 기본값으로 다시 시작한다. 설정 파일이 손상된 경우에만 사용자에게 알린다(브리핑은 다시 수집하면 됨).
- 메모리에 전부 올려도 문제없는 크기이므로 인덱싱·쿼리 계층을 두지 않는다.

### 보관 정책

- **당일치만 유지**한다. 새 브리핑이 생성되면 `briefing.json`을 통째로 덮어쓴다. 지난 날짜 조회 화면은 만들지 않는다.
- 예외로 `archive-index.json`(노션에 저장한 기사의 URL 해시 + 페이지 ID)만 남긴다. 같은 기사가 다시 올라왔을 때 중복 저장을 막고 "이미 노션에 있음"을 표시하기 위함. 5,000건을 넘으면 오래된 것부터 지운다.
- 장기 보관이 필요한 기사는 사용자가 [노션 저장]으로 직접 남긴다.

## 12. 남은 확인 사항

구현을 막지는 않지만 진행하면서 확정할 항목들. 기본 방향을 적어 두고, 해당 마일스톤에서 다시 확인한다.

1. **언어** (M4) — UI와 요약 모두 한국어로 고정해 시작한다. 영어 논문도 한국어로 번역·요약한다. 원문 용어를 병기할지는 요약 프롬프트 튜닝 단계에서 결정.
2. **RSS 소스 목록** (M3) — 키 없이 쓰는 최후 폴백용 기본 RSS 피드 목록을 어디까지 내장할지(국내 주요 언론사 피드 등). 구현 시 후보를 정리해 확인 요청 예정.
3. **노션 안내 그림** (M6) — 온보딩 3단계(페이지에 통합 연결 권한 주기) 설명에 쓸 캡처 이미지가 필요하다. 노션 UI는 바뀌므로, 그림 없이 텍스트만으로 시작하고 실제 화면을 보며 보강하는 편이 안전하다.
4. **업데이트 채널** (M7) — 정식 릴리즈만 볼지, 프리릴리즈(베타)도 받을지. 기본은 정식만.
